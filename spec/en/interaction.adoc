= Web pages and apps
include::_fpsot-terms.adoc[]

These rules cover how people use the screens of a product with a keyboard, a pointer or an assistive technology.
Each rule names the success criteria of link:https://www.w3.org/TR/WCAG22/[version 2.2] of the {abbr-wcag-first} that it builds on.

== Keyboard and structure

[[ACC-020]]
*ACC-020.* Every function MUST work with a keyboard alone, with no keyboard trap.
The focus order MUST follow the reading order of the screen.
A person MUST be able to turn off or remap each shortcut that uses a single character key.
Many people cannot use a mouse, and screen reader users move with the keyboard.
Criteria 2.1.1, 2.1.2, 2.1.4 and 2.4.3 set these rules.

[[ACC-021]]
*ACC-021.* A product MUST build each control from its native {abbr-html-first} element, such as `button` or `input`.
Where no native element exists, the control MUST follow link:https://www.w3.org/TR/wai-aria-1.2/[WAI-ARIA 1.2] for roles, states and properties.
Every control MUST expose its name, role and value to assistive technologies, as in criterion 4.1.2.
Native elements already work with assistive technologies and keyboards.
Wrong {abbr-aria-first} attributes are worse than none, because they give false information.

[[ACC-022]]
*ACC-022.* Each page MUST have a title that names its purpose.
It MUST mark its main content and its navigation as landmarks, and use headings in order.
It MUST offer a link to skip to the main content.
Screen reader users move by headings and landmarks to find what they need.
Criteria 1.3.1, 2.4.1 and 2.4.2 set these rules.
The {abbr-fpsot-first} internationalization specification sets how to mark the language of each page and passage.

== Forms and sign-in

[[ACC-023]]
*ACC-023.* Each form field MUST have a visible label that the code ties to the field.
The label or the help text MUST state the expected format, and whether the field is required.
An error message MUST name the field and the problem, and suggest a fix when the product knows one.
A form with several errors SHOULD show a summary at the top that links to each field.
People need to know what to enter and how to correct a mistake.
Criteria 1.3.1, 3.3.1, 3.3.2 and 3.3.3 set these rules.

[[ACC-024]]
*ACC-024.* A sign-in step MUST NOT depend on a memory test or a puzzle alone.
It MUST allow pasting and password managers, and SHOULD offer a method that needs no memory, such as a passkey.
A process MUST NOT ask for the same information twice, unless it fills in the answer or offers it.
Memory tests block many people with cognitive disabilities from their own records.
Criteria 3.3.7 and 3.3.8 set these rules.

[[ACC-025]]
*ACC-025.* A status message, such as "Saved" or "3 results", MUST reach assistive technologies without moving the focus.
A person MUST be able to turn off, adjust or extend a time limit, unless the limit is essential.
Before a session ends, a product MUST warn the person and give 20 seconds or more to extend it.
People who read or type slowly need more time.
Criteria 2.2.1 and 4.1.3 set these rules.

[[ACC-026]]
*ACC-026.* Help, such as a contact link, MUST appear in the same place on each page that offers it.
Navigation that repeats on several pages MUST keep the same order.
People find help faster when it does not move.
Criteria 3.2.3 and 3.2.6 set these rules.

== Mobile apps

[[ACC-027]]
*ACC-027.* A mobile app MUST meet the baseline as link:https://www.w3.org/TR/wcag2ict-22/[WCAG2ICT] applies it to software.
It MUST also meet clause 11 of link:https://www.etsi.org/deliver/etsi_en/301500_301599/301549/04.01.01_60/en_301549v040101p.pdf[EN 301 549 V4.1.1], on software.
An app MUST build on the accessibility services of its platform, so that the platform screen readers work.
It MUST follow the text size of the system up to the largest size, and work in both orientations.
The {abbr-wcag} criteria target the web, and these sources set how they apply inside an app.
Criterion 1.3.4 sets the rule on orientation.

[[ACC-028]]
*ACC-028.* A function that uses dragging or a complex gesture MUST also work with one simple tap or click.
A function that works by shaking or tilting the device MUST also work through a control.
The person MUST be able to turn off that motion.
Some people cannot drag, pinch or hold a device steady.
Criteria 2.5.1, 2.5.4 and 2.5.7 set these rules.
